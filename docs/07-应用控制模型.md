# 07 应用控制模型

这一章解释 AppleScript「为什么长这样」。理解了它，后面所有 `tell` 相关问题都能自己推断。

## 7.1 一切皆 Apple Event

AppleScript 不是直接调用函数，而是**给另一个进程发一条消息（Apple Event）**，对方处理完再回消息。

```applescript
tell application "Finder"
	count of files of folder "Macintosh HD:Users:taylor:Desktop:"
end tell
```

实际发生的事：

1. Finder 没运行 → 先启动它
2. 发送 `core / cnte` 事件，参数是一个 folder 引用
3. Finder 计算后回一个整数
4. AppleScript 拿到结果

所以：

- **慢**：每次交互都有进程间通信开销。循环里逐条问 Finder 会非常慢。
- **可能超时**：默认 60 秒，见 `docs/06-错误处理与调试.md` §6.3
- **可能弹权限框**：第一次控制某个 App 时，macOS 会要求授权（TCC）
- **App 没运行也会被启动**：`tell application "X"` 就会启动 X。
  只想查询、不想启动，用 `using terms from`（见 §7.4）或 `tell application "System Events"` 判断进程是否存在。

## 7.2 术语解析规则（最重要的一节）

⚠️ 在 `tell` 块里，**每个词先按目标 App 的字典解析，找不到才回退到 AppleScript 自己的词**。

这会导致几类经典错误：

### ① 调用自己的 handler 忘了加 `my`

```applescript
on padZero(n)
	return text -2 thru -1 of ("0" & (n as text))
end padZero

tell application "Finder"
	padZero(5)      -- ❌ Finder doesn't understand the "padZero" message (-1708)
	my padZero(5)   -- ✅
end tell
```

### ② Standard Additions 命令：能省 `my`，但加了必须带括号

```applescript
with timeout of 10 seconds
	tell application "Finder"
		set p to path to home folder            -- ✅ 实测返回 Macintosh HD:Users:taylor:
		set n to offset of "a" in "abc"         -- ✅ 实测返回 1
		set s to do shell script "echo hi"      -- ✅ 实测返回 hi
	end tell
end timeout
```

`path to`、`offset`、`current date`、`do shell script`、`read`/`write`、`quoted form of` 都属于这类。
Finder 字典里没有这些术语，编译器就**回退到 StandardAdditions**，并留在本地（osascript 进程）执行，
并不会真的发一个 Apple Event 给 Finder。所以不加 `my` 通常也能跑。

但一旦决定加 `my`，**后面必须用括号把整条命令包起来**：

```applescript ❌
tell application "Finder"
	set p to my path to home folder           -- ❌ A command name can't go after this "my". (-2740)
	set p to my (path to home folder)         -- ✅
	set n to my offset of "a" in "abc"        -- ❌ 同样 -2740
	set n to my (offset of "a" in "abc")      -- ✅
end tell
```

原因：`my` 后面只能跟**一个表达式**。不加括号时，解析器会把 `my path` 当成「当前脚本的 `path` 属性」，
剩下的 `to home folder` 就无处安放了。

⚠️ 真正**必须**加 `my` 的是另外两类情况，别把它们和标准附加命令混为一谈：

1. 调用本脚本自己的 handler（§7.2①）→ 不加就报 -1708。
2. 名字和目标 App 的属性撞车（§7.2③）→ 不加就会被当成 App 的属性。

经验法则：`tell` 块里的通用命令写成 `my (…)` 最稳妥（明确归属、不会被 App 字典抢走），
但**括号不能漏**——这是本节最容易踩的编译错误。

### ③ 变量名和 App 的属性名撞车

```applescript ❌
set text to "abc"        -- ❌ 编译期就挂：Can't set text to "abc". Access not allowed. (-10003)
set name to "abc"        -- ❌ 编译通过，运行期报：Can't set name to "abc". (-10006)
set id to 5              -- ❌ 编译通过，运行期报：Can't set id to 5. (-10006)
set version to "1.0"     -- ⚠️ 顶层能用，一进 tell 块就变味（见下）
```

在 `tell` 块里，这些名字会被解释成 **App 的属性**，而不是你的局部变量。本机实测：

```applescript
tell application "Finder"
	get version      --> "26.4"    ← Finder 自己的版本号，不是你设的 "1.0"
	get name         --> "Finder"
end tell
```

**变量名请至少两个单词**：`fileName`、`theText`、`recordId`。
完整的「不能当变量名」清单见 §2.9 与 §16.1③。

### 规则总结

| 你想用的东西 | 在 tell 块里的写法 |
| --- | --- |
| 自己脚本的 handler | `my handlerName(…)` |
| Standard Additions 命令 | 可省略 `my`；要加就写 `my (path to home folder)` |
| 脚本顶层的 property/变量 | `my propName` |
| 目标 App 的命令/属性 | 直接写 |
| AppleScript 核心语法（`set`/`if`/`repeat`/`&`） | 直接写，不受影响 |

💡 **最省心的做法：把「自己的逻辑」放在 tell 块外面，tell 块里只留必要的 App 调用。**

```applescript
-- ❌ 不好：所有逻辑都塞在 tell 里
tell application "Finder"
	set fileList to name of every file of folder theFolder
	set sortedList to my sortList(fileList)
	log sortedList
end tell

-- ✅ 好：tell 块只做一件事
tell application "Finder"
	set fileList to name of every file of theFolder
end tell
set sortedList to my sortList(fileList)
log sortedList
```

## 7.3 对象引用（reference）

App 返回的对象常常是**引用**而不是值。引用是「一条从 App 根对象出发的路径」：

```applescript
tell application "Finder"
	set f to file "note.txt" of folder "Docs" of home
	-- f 不是文件内容，而是"home 下 Docs 里那个 note.txt"这条路径
	name of f          --> 此刻才真的去问 Finder
end tell
```

带来两个后果：

1. **惰性求值**：拿到引用时还没查询，用时才发事件。
2. ⚠️ **引用会失效**：如果对象被移动/重命名/删除，旧引用就指向不存在的东西。

实测例子：

```applescript
tell application "Finder"
	set nf to make new folder at someFolder with properties {name:"tmpA"}
	set name of nf to "tmpB"
	name of nf       -- ❌ 报错 -1700/-43：nf 仍指向 "tmpA"，而它已经不存在了
	set nf2 to folder "tmpB" of someFolder
	name of nf2      -- ✅
end tell
```

**改名/移动之后必须重新取引用。**

## 7.4 `using terms from`：只借词，不启动

```applescript
using terms from application "Finder"
	set theRef to file "note.txt" of folder "Docs" of home
end using terms from
-- 此时 Finder 还没被启动，theRef 只是一个待解析的引用
```

用途：

- **编译期**借用某个 App 的术语，让脚本在目标 App 不存在时也能编译通过
- 构造引用而不立刻触发通信
- 写「可选支持某个 App」的脚本

⚠️ `using terms from` 块里**不能真的执行**该 App 的命令，只能构造引用。

## 7.5 怎么查一个 App 支持什么

### 方法一：Script Editor 字典（⇧⌘O）

最直观。左侧选 App，能看到 Suite → Class / Command / Property 三层结构。

### 方法二：命令行 `sdef`

```bash
# 列出所有命令
sdef /Applications/Safari.app | grep -oE '<command name="[^"]+"'

# 列出所有类
sdef /Applications/Safari.app | grep -oE '<class name="[^"]+"'

# 看某个命令的完整签名
sdef /Applications/Safari.app | grep -A12 '<command name="do JavaScript"'

# 格式化输出便于阅读
sdef /Applications/Safari.app | xmllint --format - | less
```

### 方法三：让 App 自己报告

```applescript
tell application "Safari"
	get version
end tell
```

### 常见 App 的字典路径

```
/Applications/Safari.app                          ← 注意不在 /System/Applications
/System/Applications/Mail.app
/System/Applications/Calendar.app
/System/Applications/Reminders.app
/System/Applications/Notes.app
/System/Applications/Music.app
/System/Applications/Photos.app
/System/Applications/Maps.app
/System/Applications/Messages.app                   ← ⚠️ 基本无脚本支持
/System/Applications/TextEdit.app
/System/Applications/Preview.app                    ← ⚠️ 无字典
/System/Library/CoreServices/Finder.app
/System/Library/CoreServices/System Events.app
/Applications/Microsoft Excel.app                   ← Office 系列字典非常丰富
/Applications/Google Chrome.app
```

⚠️ **不是所有 App 都能被脚本控制。** Preview、Messages（大部分功能）、很多第三方 App
根本没有脚本字典。判断方法：

```bash
sdef /System/Applications/Preview.app 2>&1 | head -3
# 若输出为空或报错，说明该 App 不可脚本化
```

不可脚本化的 App 只能走 **UI Scripting**（模拟点击），见 `docs/10-SystemEvents与界面自动化.md`。

## 7.6 `whose` 过滤

`whose` 让 App 在**它自己那边**过滤对象，比把全部对象取回来再在 AppleScript 里筛快得多：

```applescript
tell application "Finder"
	set bigFiles to (every file of folder theFolder whose size > 100000000)
	set logs to (every file of folder theFolder whose name extension is "log")
	set recentDirs to (every folder of theFolder whose modification date > (current date) - (7 * days))
end tell
```

⚠️ `whose` 里的属性名必须是**目标 App 字典里的名字**，不是 AppleScript 的通用词。

⚠️ `whose` 不支持任意复杂表达式。遇到不支持的情况会静默返回空或报错，
此时改用「取回全部 + AppleScript 里 `repeat` 过滤」。

System Events 也支持：

```applescript
tell application "System Events"
	set visibleApps to (name of every process whose background only is false)
	set theFront to (first process whose frontmost is true)
end tell
```

## 7.7 批量操作：性能要点

```applescript
-- ❌ 慢：N 个文件 = N 次 Apple Event 往返
repeat with f in fileList
	tell application "Finder" to set name of f to (name of f) & ".txt"
end repeat

-- ✅ 快：一次性取回所有名字，本地处理，再批量写回
tell application "Finder"
	set oldNames to name of every file of theFolder
end tell
set newNames to {}
repeat with n in oldNames
	set end of newNames to ((contents of n) & ".txt")
end repeat
tell application "Finder"
	repeat with i from 1 to count of newNames
		set name of file (item i of oldNames) of theFolder to (item i of newNames)
	end repeat
end tell
```

核心原则：**把「跨进程通信」的次数降到最低，把计算留在 AppleScript 本地做。**

# 06 错误处理与调试

## 6.1 try / on error

```applescript
try
	set n to userInput as integer
on error
	set n to 0
end try
```

拿到完整的错误信息（四个变量全部实测可用）：

```applescript
try
	error "自定义消息" number 5001 from "来源对象" to "目标对象"
on error errMsg number errNum from errFrom to errTo
	log errMsg     --> "自定义消息"
	log errNum     --> 5001
	log errFrom    --> "来源对象"
	log errTo      --> "目标对象"
end try
```

⚠️ `on error` 的变量名可以随便取，但**顺序和关键字必须固定**：
`on error <消息> number <编号> from <来源> to <目标>`，后面的子句都可以省略。

### 主动抛出错误

```applescript
error                                          -- 抛出一个通用错误
error "文件不存在"                              -- 带消息
error "文件不存在" number -43                   -- 带消息和编号
error number -128                              -- 模拟「用户取消」
```

### 重新抛出 / 向上冒泡

```applescript
try
	doSomething()
on error errMsg number errNum
	log "记录一下：" & errMsg
	error errMsg number errNum          -- 重新抛出，让上层处理
end try
```

### ⚠️ 一定要放行「用户取消」

用户点「取消」会抛 `-128`。如果你的 `try` 把它吞掉了，脚本会表现得像「点了取消还在继续跑」。
标准写法：

```applescript
try
	set theFile to choose file with prompt "选择文件"
on error errMsg number errNum
	if errNum is -128 then
		-- 用户主动取消，安静退出
		return
	end if
	error errMsg number errNum          -- 其他错误继续往上抛
end try
```

或者把「取消」显式排除在捕获之外：

```applescript
try
	set theFile to choose file
on error number errNum
	if errNum is not -128 then error number errNum
end try
```

## 6.2 常见错误码对照表

| 错误码 | 含义 | 典型触发场景 |
| --- | --- | --- |
| **-128** | 用户取消 | 点了对话框的「取消」按钮 |
| **-1700** | Can't make X into type Y（类型转换失败） | `"abc" as integer`；把引用列表当文本用 |
| **-1708** | 对象不理解该消息 | 方法名拼错；`nsArray` 命名撞车（见 §2.9） |
| **-1712** | 用户取消 / 超时 | Apple Event 超时 |
| **-1719** | Can't get 该元素（非法索引） | `item 99 of {1,2}` |
| **-1723** | Access not allowed | 沙箱/权限限制 |
| **-1727** | Expected a reference | `count of items of <alias>`（见 §9） |
| **-1728** | Can't get 该对象 | 文件/App 不存在；`butlast of {…}` |
| **-1729** | Can't make 该对象 | 类型不匹配的赋值 |
| **-1730** | 无效的参数 | 参数值非法 |
| **-1741** | 未知的错误 | 通用 |
| **-10000** | Apple Event 处理失败 | 通用 |
| **-10003** | Access not allowed（设置只读属性） | `set me to …` |
| **-10006** | Can't set 该属性 | 属性只读或名字冲突 |
| **-10010** | Handler 不存在 | 忘了加 `my` |
| **-10011** | 参数个数不对 | 少传/多传参数 |
| **-25211** | 需要辅助功能权限 | UI Scripting 未授权 |
| **-1743** | 未授权（自动化权限） | 控制其他 App 被 TCC 拒绝 |
| **-2740 / -2741 / -2742** | 编译期语法错误 | `as` 连用、关键字冲突等 |
| **-43** | 文件未找到（fnfErr） | 路径错误、文件已删 |
| **-47** | 文件被占用 | 文件已打开 |
| **-49** | 写入错误 | 磁盘/权限问题 |
| **-50** | 参数错误（paramErr） | 传参类型不对 |
| **-120** | 目录访问被拒 | 沙箱限制 |
| **-15000** | 未授权发送 Apple Event | 自动化权限被拒 |

⚠️ 注意区分 **-1743**（用户/系统拒绝了自动化权限）和 **-25211**（缺少辅助功能权限），
两者都要去「系统设置 → 隐私与安全性」处理，但入口不同。

## 6.3 超时控制

```applescript
with timeout of 30 seconds
	tell application "Finder" to …
end timeout
```

默认 Apple Event 超时是 **60 秒**（某些操作是 2 分钟）。长时间操作要显式放宽。

⚠️⚠️ **`with timeout` 只对「发给其他 App 的 Apple Event」生效，对本地计算和 `delay` 无效。**
实测：

```applescript
with timeout of 1 second
	delay 3        -- ⚠️ 依然会等满 3 秒，不会超时中断
end timeout
```

`delay` 是 Standard Additions 的本地命令，不产生 Apple Event，所以 timeout 管不到它。
要给本地长任务设超时，只能自己做时间检查：

```applescript
set deadline to (current date) + 30
repeat while not isDone
	if (current date) > deadline then exit repeat
	-- …
end repeat
```

### 不等待 App 回应

```applescript
tell application "SomeApp"
	ignoring application responses
		doSomethingSlow()      -- 发出去就返回，不等结果
	end ignoring
end tell
```

⚠️ 用 `ignoring application responses` 之后**拿不到返回值**，也无法知道是否成功。
只适合「发完就不管」的场景（如让 App 后台打印、退出）。

## 6.4 log 与调试输出

```applescript
log "调试信息"
log {a:1, b:2}
```

⚠️ **`log` 输出到 stderr，不是 stdout**（实测）。所以：

```bash
osascript myscript.applescript            # 两者都显示在终端
osascript myscript.applescript 2>/dev/null # 屏蔽 log，只看返回值
osascript myscript.applescript 2>debug.log # log 重定向到文件
```

这个特性很好用：**`log` 走 stderr，`return` 走 stdout，两者互不干扰**，
可以在 shell 里安全地捕获脚本返回值。

⚠️ `log` 会强制求值，对大列表/复杂引用会带来明显性能损耗，正式发布前要清掉。

### 自己写一个可开关的日志器

```applescript
property debugMode : true
property logFile : missing value

on logMsg(msg)
	set stamp to my formatStamp(current date)
	set logLine to stamp & "  " & msg
	if my debugMode then log logLine
	if my logFile is not missing value then
		try
			set fh to open for access file (my logFile) with write permission
			write (logLine & linefeed) to fh starting at eof as «class utf8»
			close access fh
		on error
			try
				close access file (my logFile)
			end try
		end try
	end if
end logMsg
```

⚠️ 这里的局部变量**不能叫 `line`**：`set line to …` 会直接编译失败
（`Can't set line to …  Access not allowed.` -10003），`repeat with line in …` 也一样报错。
`line` 和 `text`、`word`、`paragraph`、`character`、`item` 都是 AppleScript 的文本元素类名（§2.9）。

⚠️ 写文件的 `try` 里一定要兜底 `close access`，否则文件句柄泄漏会导致后续
`open for access` 报 `-49` 或 `-50`。

## 6.5 调试技巧

### ① 用 Script Editor 的事件日志

菜单 **显示 → 事件日志**（⇧⌘2）。它会记录脚本发出的每一个 Apple Event 和收到的回复：

```
Finder got: count every file of folder "…"
Finder replied: 42
```

当 App「不听话」时，这里能看出到底是**你发的命令不对**，还是**App 返回了意外结果**。
这是排查应用控制问题的第一手段。

### ② 选中局部运行

在 Script Editor 里选中几行再按 ⌘R，只执行选中部分，结果直接显示在下方。
排查表达式时比反复跑整个脚本快得多。

### ③ 在命令行里加「探针」

```bash
# 单独验证一个表达式
osascript -e 'set d to current date' -e 'return (year of d as text)'

# 查看某个值的类型（类型错误占 AppleScript bug 的一半）
osascript -e 'return (class of (item 1 of {"a"})) as text'
```

### ④ 用 `-s s` 看清楚数据结构

```bash
osascript -s s -e 'return {"a", {"b"}}'    --> {"a", {"b"}}
osascript -s h -e 'return {"a", {"b"}}'    --> a, b        ← 嵌套信息全丢了
```

调试返回复杂结构时，**永远加 `-s s`**。

### ⑤ 断言式防御

在 handler 开头校验入参，比在深处报出莫名错误好得多：

```applescript
on processFile(theFile)
	if theFile is missing value then error "processFile: 参数为空" number -15000
	if class of theFile is not alias then
		try
			set theFile to theFile as alias
		on error
			error "processFile: 无法转成 alias，收到的是 " & (class of theFile as text)
		end try
	end if
	-- … 正式逻辑
end processFile
```

### ⑥ 定位「哪个 tell 块出问题」

`tell` 块内的命令会先按目标 App 的字典解析。如果 App 不认识，你会看到
`<App> doesn't understand the "xxx" message (-1708)`。
这时通常是：

- 你想调用的是**自己脚本里的 handler** → 加 `my`
- 你想调用的是 **Standard Additions 命令**（如 `offset`、`path to`）→ 加 `my`，或把它移出 tell 块
- 拼写/术语错误 → 用 `sdef` 核对

详见 `docs/07-应用控制模型.md`。

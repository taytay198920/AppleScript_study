# 02 语言核心

## 2.1 变量与赋值

AppleScript 没有类型声明，也没有 `let`/`var`，直接 `set`：

```applescript ❌
set userName to "Taylor"      -- 推荐写法：to
set 5 to myNumber             -- ❌ 错，左边必须是变量
set myNumber to 5
myNumber                      -- 单独一行变量名 = 取值（等价于 get myNumber）
```

`to` 和 `=` 都能用，习惯上赋值用 `to`，比较用 `=`：

```applescript
set x = 5        -- 合法但不推荐
if x = 5 then …  -- 比较
```

⚠️ **变量不需要预先声明，拼错变量名不会报错**，而是会创建一个新变量。
这是 AppleScript 最难查的 bug 来源之一。建议在脚本开头集中声明：

```applescript
set sourceFolder to missing value
set targetFolder to missing value
set fileList to {}
```

### 常量关键字

这些是保留的，不能用作变量名：

| 常量 | 值 |
| --- | --- |
| `true` / `false` | 布尔值 |
| `missing value` | 「空」，类似 null |
| `linefeed` | `\n`（id 10） |
| `return` | `\r`（id 13） |
| `tab` | `\t`（id 9） |
| `space` | 一个空格 |
| `quote` | 一个双引号 `"` |
| `pi` | 3.14159… |

⚠️ **AppleScript 没有 `null` 值。** 表示「没有东西」统一用 `missing value`。
（`null` 在 AppleScript 里是一个 *class* 名，不是空值，别拿它当 nil 用。）

```applescript
set foundItem to missing value
if foundItem is missing value then …
```

⚠️ AppleScript 的「换行」历史上是 `\r`（`return`），而 Unix 是 `\n`（`linefeed`）。
写文件给 Unix 工具用时要显式用 `linefeed`，见 `docs/09-Finder与文件读写.md`。

## 2.2 数据类型

| 类型 | 示例 | `class of` 返回 |
| --- | --- | --- |
| 整数 | `42`、`-7` | `integer` |
| 实数 | `3.14`、`2.0` | `real` |
| 文本 | `"hello"` | `text` |
| 布尔 | `true` | `boolean` |
| 列表 | `{1, 2, "三"}` | `list` |
| 记录 | `{name:"A", age:3}` | `record` |
| 日期 | `current date` | `date` |
| 别名 | `alias "Macintosh HD:Users:"` | `alias` |
| 文件引用 | `POSIX file "/tmp/a.txt"` | `file` |
| 脚本对象 | `script … end script` | `script` |
| 空值 | `missing value` | `missing value` |

```applescript
class of "x"      --> text
class of 1        --> integer
class of 1.5      --> real
class of {1}      --> list
```

⚠️ 字符串的类是 `text`，不是 `string`。但 `as string` 也能用（`string` 是 `text` 的别名）。

### 文本（text）的三种等价说法

`text`、`string`、`Unicode text` 在现代 AppleScript 里基本等价，都能用来强制转换：

```applescript
42 as text          --> "42"
42 as string        --> "42"
```

## 2.3 运算符

### 算术

| 运算符 | 说明 | 示例 |
| --- | --- | --- |
| `+` `-` `*` `/` | 四则运算 | `7 / 2` → `3.5` |
| `div` | 整数除法 | `7 div 2` → `3` |
| `mod` | 取余 | `7 mod 2` → `1` |
| `^` | 幂 | `2 ^ 10` → `1024.0`（返回 real） |
| `-` | 一元负号 | `-x` |

⚠️ `/` 永远返回实数。要整数结果用 `div`，或 `as integer`（会**四舍五入**，不是截断）：

```applescript
(7 / 2) as integer   --> 4   （3.5 四舍五入）
2.7 as integer       --> 3
```

### 比较

`=`（等于）、`≠` 或 `is not equal to`、`<`、`>`、`≤` 或 `is less than or equal to`、`≥`。

等价的英文写法（可读性更好，也更安全）：

```applescript
if x is equal to 5 then …
if x is not 5 then …
if x is greater than 5 then …
if x is in {1, 2, 3} then …     -- 成员判断
if x contains "ab" then …       -- 文本/列表包含
if s starts with "App" then …
if s ends with "ipt" then …
```

实测：

```applescript
"AppleScript" starts with "App"    --> true
"AppleScript" ends with "ipt"      --> true
"AppleScript" contains "Script"    --> true
"b" is in {"a", "b"}               --> true
```

### 逻辑

`and`、`or`、`not`。**支持短路求值**：

```applescript
if (count of lst) > 0 and (item 1 of lst) = "x" then …   -- 安全
```

### 字符串连接

`&`：

```applescript
"a" & "b"          --> "ab"
```

⚠️ **`&` 的结果类型由左操作数决定**：

```applescript
5 & " apples"      --> "5 apples"   （左边是数字 → 结果是文本）
"count: " & 5      --> "count: 5"
5 & {1}            --> ❌ 报错 -1728，数字无法拼接列表
{1} & 5            --> {1, 5}       （左边是列表 → 结果是列表）
```

要确保得到文本，把数字放右边或显式转换：`"n=" & (5 as text)`。

## 2.4 类型转换（coercion）

用 `as`：

```applescript
"42" as integer        --> 42
"3.14" as real         --> 3.14
42 as text             --> "42"
{1, 2} as text         --> 依赖 text item delimiters，见 docs/03
42.7 as integer        --> 43（四舍五入）
```

⚠️ **连续 `as` 必须加括号**，否则编译报错「A class name can't go after this identifier」：

```applescript
month of d as integer as text          -- ❌ 语法错误
((month of d) as integer) as text      -- ✅
```

转换失败会抛错 `-1700`（Can't make … into type …），要容错就包 `try`：

```applescript
try
	set n to userInput as integer
on error
	set n to 0
end try
```

## 2.5 `set` 是共享引用，`copy` 才是副本

这是 AppleScript 最容易踩的语义坑。**列表、记录、日期都是引用类型**：

```applescript
set a to {1, 2, 3}
set b to a          -- b 和 a 指向同一个列表
set end of b to 4
a                   --> {1, 2, 3, 4}   ⚠️ a 也变了！
```

用 `copy` 得到独立副本：

```applescript
set c to {1, 2, 3}
copy c to d
set end of d to 4
c                   --> {1, 2, 3}
d                   --> {1, 2, 3, 4}
```

**日期（date）同样是引用类型**，这点最容易被忽略（实测）：

```applescript
set d1 to current date
set d2 to d1          -- 共享同一个日期对象
set time of d2 to 0
time of d1            --> 0   ⚠️ d1 也被改成零点了！

set d3 to current date
copy d3 to d4         -- 独立副本
set time of d4 to 0
time of d3            --> 85592  ✅ 原值保留
```

⚠️ **handler 参数也是按引用传递的**。即使你在函数里 `set localCopy to theParam`，
修改 `localCopy` 仍然会影响调用方的变量：

```applescript
on mutateParam(x)
	set localCopy to x      -- 并没有真的拷贝！
	set time of localCopy to 0
end mutateParam

set d to current date
my mutateParam(d)
time of d                 --> 0   ⚠️ 被改了
```

函数内要保护入参，第一件事就是 `copy`：

```applescript
on startOfDay(theDate)
	copy theDate to t       -- ✅
	set time of t to 0
	return t
end startOfDay
```

注意方向：`copy c to d` 是「把 c 拷到 d」，和 `set d to c` 的语序相反。

标量（integer/text/boolean）没有这个问题，因为它们是不可变的。

## 2.6 作用域与 `my` / `its`

AppleScript 有三级作用域：

| 层级 | 声明位置 | 可见范围 |
| --- | --- | --- |
| `global` | handler 内用 `global x` 声明 | 整个脚本 |
| `property` | 脚本顶层 `property x : 1` | 整个脚本，且**编译后保存**，运行间会保留值 |
| `local` | handler 内直接 `set` | 该 handler |

```applescript
property runCount : 0        -- 值会在 .scpt/.app 中持久保存
global logList

on run
	set logList to {}
	set runCount to runCount + 1
	my appendLog("第 " & runCount & " 次运行")
	return logList
end run

on appendLog(msg)
	global logList
	set end of logList to msg
end appendLog
```

⚠️ 一旦脚本里写了显式的 `on run`，**顶层就不能再有任何可执行语句**（`property`/`global` 声明不算）。
把 `set logList to {}` 放在顶层会直接编译失败：
`The run handler is specified more than once, or there were top-level commands in addition to the run handler. (-2752)`。
初始化语句要挪进 `on run`，或者干脆改用 `property logList : {}`。

⚠️ **在 handler 内部调用同脚本的另一个 handler，必须加 `my`（或 `its`）前缀**：

```applescript
on run
	pad2(5)        -- ❌ 找不到命令
	my pad2(5)     -- ✅
end run

on pad2(n)
	return text -2 thru -1 of ("0" & (n as text))
end pad2
```

原因：不加前缀时，AppleScript 会把它当成「发给当前 tell 目标 App 的命令」，而那个 App 不认识 `pad2`。

⚠️ 同理，在 `tell` 块里访问脚本顶层的变量/handler，也建议加 `my`，否则可能被解释成 App 的属性。

## 2.7 `considering` / `ignoring`

控制字符串比较时的规则：

```applescript
"Abc" = "abc"                  --> false（默认区分大小写）

ignoring case
	"Abc" = "abc"              --> true
end ignoring

considering case
	"Abc" = "abc"              --> false（显式声明）
end considering

ignoring punctuation and white space
	"a-b c" = "abc"            --> true
end ignoring
```

可用的选项：`case`、`diacriticals`、`hyphens`、`punctuation`、`white space`、`numeric strings`。
多个选项用 `and` 连接。

⚠️ 这些语句只影响**字符串比较**，不影响 `text item delimiters` 的切分行为。

## 2.8 续行与注释

```applescript
-- 单行注释
# 也是单行注释（但不推荐，某些工具处理不好）

(* 多行
   注释 *)

-- 续行：行尾加 ¬（Option+L 输入），或在编辑器里直接换行
set theResult to someVeryLongCommandName(firstParameter, ¬
	secondParameter, thirdParameter)
```

⚠️ 续行符 `¬` 后面**不能有任何字符**，包括空格，否则编译失败。

## 2.9 保留字与「不能当变量名」的坑

### 语法保留字

```
about above after against and apart from around as aside from at back before beginning
behind below beneath beside between but by considering contain contains continue copy div
does eighth else end equal equals error every exit fifth first for fourth from front get
given global if ignoring in instead of into is it its last local me middle mod my ninth
not of on onto or out of over prop property put ref reference repeat returning script
second set seventh since sixth some tell tenth that the then third through thru times to
transaction try until where while whose with without
```

如果一定要用，加 `|` 竖线转义（实测 `set |class| to "数学"` 可用）。

### ⚠️ 实测：一批「看起来无害但会炸」的变量名

下面这些名字在 macOS 26.6 上实测**无法用作变量名**，但都不在官方保留字列表里，
报错信息还各不相同，极难定位：

| 变量名 | 报错 | 原因 |
| --- | --- | --- |
| `st` `nd` `rd` `th` | `Expected expression but found "st"` (-2741) | 序数后缀是未公开的保留标记 |
| `the` | `Expected expression but found "to"` (-2741) | 定冠词是语法的一部分 |
| `as` `is` `in` `of` `to` `if` `on` `or` | `Expected expression but found …` (-2741) | 关键字 |
| `my` `its` | `A "to" can't go after this "my"` (-2740) | 关键字 |
| `ref` | `A end of line can't go after this number` (-2740) | 关键字 |
| `it` `me` | `Can't set … Access not allowed` (-10003) | 指向当前脚本，只读 |
| `line` `text` `item` | `Can't set line to 5. Access not allowed` (-10003) | 文本元素类名，只读 |
| `no` `up` | `Can't set … Access not allowed` (-10003) | 是枚举常量 |
| `app` | `Can't set application to 1` (-10003) | `app` 是 `application` 的缩写 |
| `id` `key` | `Can't set id to 1` (-10006) | 是标准属性名 |
| `log` | `Can't set log of 1 to …` (-10006) | `log` 是命令 |
| `lines` | `Can't set every line to {…}` (-10006) | `lines` 被解析成 `every line` |

⚠️ 同理还有 `words`、`paragraphs`、`items`、`characters` 这类「AppleScript 认为是集合元素」的复数名词，
实测 `set lines to …` 会报 `Can't set every line to …`。
集合类变量请写成 `theLines`、`lineList`、`wordList`。

⚠️⚠️ **最坑的两个：`nd` 和 `line`**

- `nd`：写日期脚本时很容易顺手 `set nd to current date`（new date 的缩写），
  然后得到一个完全看不懂的编译错误。同类的 `st`（state）、`rd`（record）、`th` 也一样不能用。
- `line`：**逐行处理文本文件时几乎必然会用到**，但它连 `repeat with` 的循环变量都当不了：

```applescript ❌
repeat with line in {"a", "b"}   -- ❌ Expected variable name or property but found class name. (-2741)
end repeat

repeat with ln in {"a", "b"}     -- ✅ 换成 ln / theLine / aLine
end repeat
```

⚠️ **还有一类「大小写不敏感撞名」的坑**：AppleScript 标识符不区分大小写，
所以 `set nsArray to current application's NSArray's arrayWithArray:lst` 会失败 ——
`NSArray` 被解析成了你那个叫 `nsArray` 的局部变量。用 AppleScriptObjC 时避开 `nsXxx` 这种命名。

### 安全的命名习惯

- 变量用 `lowerCamelCase` 且**至少两个单词**：`targetDate`、`fileList`、`outputText`
- handler 参数加前缀：`theDate`、`theText`、`sourceFolder`
- 需要和 ObjC 打交道时用 `cocoaXxx` / `theXxx`，别用 `nsXxx`

# 05 控制流与函数

## 5.1 条件判断

```applescript
if x > 10 then
	set label to "大"
else if x > 5 then
	set label to "中"
else if x > 0 then
	set label to "小"
else
	set label to "非正"
end if
```

单行形式：

```applescript
if x > 10 then set label to "大"
```

⚠️ AppleScript **没有三元运算符**。等价写法：

```applescript
-- 想写： s = (n > 0) ? "正" : "非正"
set s to "非正"
if n > 0 then set s to "正"
```

### ⚠️ `if` 的条件**必须是 boolean**

和 JavaScript / Python 不同，AppleScript **不做真值转换**。实测：

```applescript
if 0 then …        -- ❌ 运行时报错 -1700  Can't make 0 into type boolean
if "" then …       -- ❌ 同样 -1700
if {} then …       -- ❌ 同样 -1700
if false then …    -- ✅ 正常
```

所以「非空判断」必须显式写：

```applescript
if (count of lst) > 0 then …
if theText is not "" then …
if theValue is not missing value then …
```

⚠️ 这个错误是**运行期**才抛出的，编译（⌘K）不会报，所以很容易漏到线上。

## 5.2 循环

### 计数循环

```applescript
repeat with i from 1 to 10
	-- i 依次是 1,2,…,10
end repeat

repeat with i from 10 to 1 by -1     -- 倒序，实测输出 10 9 8 … 1
	log i
end repeat

repeat with i from 1 to 10 by 2      -- 步长 2：1,3,5,7,9
	log i
end repeat
```

实测：`repeat with i from 1 to 10` 里的 `i` 就是普通 integer（`class of i` → `integer`），
可以直接 `"n=" & i`，不需要额外处理。

**但 `repeat with x in aList` 里的 `x` 是「对列表元素的引用」**，这才是真正需要注意的地方，见下一节。

### 遍历列表：`contents of` 是必须的

```applescript
set lst to {"a", "b", "c"}

-- ❌ 存进去的是「引用」，不是值
set refs to {}
repeat with anItem in lst
	set end of refs to anItem
end repeat
refs as text
-- 运行时报错：Can't make {item 1 of {"a","b","c"}, item 2 of …, …} into type text (-1700)

-- ✅ 用 contents of 取出真实值
set vals to {}
repeat with anItem in lst
	set end of vals to (contents of anItem)
end repeat
vals as text        --> "abc"（配 delimiters 可正常拼接）
```

读写语义对照（实测）：

| 写法 | 效果 |
| --- | --- |
| `set anItem to "x"` | **只改循环变量**，原列表不变 |
| `set contents of anItem to "x"` | **真的改原列表**对应元素 |
| `contents of anItem` | 取元素的值 |
| `class of anItem` | 会自动解引用，返回元素类型（如 `text`），有迷惑性 |

```applescript
-- 批量原地加后缀
set names to {"a", "b"}
repeat with anItem in names
	set contents of anItem to (contents of anItem) & ".txt"
end repeat
names     --> {"a.txt", "b.txt"}
```

⚠️ **循环中不要修改正在遍历的列表**，会导致跳过元素或死循环。
要边遍历边改，就先 `copy` 一份，或者用倒序索引：

```applescript
repeat with i from (count of lst) to 1 by -1
	if shouldRemove(item i of lst) then delete item i of lst
end repeat
```

### 条件循环

```applescript
repeat while notDone
	-- …
	if finished then set notDone to false
end repeat

repeat until notDone          -- 与 while 相反
	-- …
end repeat

repeat                         -- 无限循环，必须靠 exit repeat 跳出
	set k to k + 1
	if k > 3 then exit repeat
end repeat
```

### 固定次数

```applescript
repeat 3 times
	doSomething()
end repeat
```

### 提前退出

```applescript
repeat with f in fileList
	if name of f ends with ".log" then exit repeat
end repeat
```

⚠️ `exit repeat` 只跳出**最内层**循环。要跳出多层，用标志变量或把逻辑放进 handler 用 `return`。

## 5.3 handler（函数）

### 基本形式

```applescript
on addNumbers(a, b)
	return a + b
end addNumbers

-- on 可以换成 to，两者完全等价
to addTwo(a, b)
	return a + b
end addTwo

-- 结束行也可以只写 end（不带 handler 名）
on addThree(a, b)
	return a + b
end
```

⚠️ **没有 `handler … end handler` 这种写法**。「handler」只是文档和圈子里对「AppleScript 函数」的称呼，
真正能用的关键字只有 `on` 和 `to`；结束行只能是 `end <handler 名>` 或单独的 `end`。
实测 `end on`、`end to`、`handler addNumbers(a, b)` 都会报
`Expected end of line, etc. but found "on"` (-2741) 之类的编译错误。

调用：

```applescript
my addNumbers(1, 2)      -- 在 handler 内部调用，必须加 my
addNumbers(1, 2)         -- 在顶层（run handler 之外）可以省略 my
```

⚠️ `return` 会**立即结束整个 handler**（不是只结束一个代码块）：

```applescript
on run
	return "A"
	return "B"      -- 永远不会执行
end run
```

### 只支持位置参数

⚠️⚠️ **AppleScript 用户自定义 handler 不支持具名参数**。以下写法全部实测编译失败：

```applescript ❌
on f(a, level:theLevel)        -- ❌ Expected "," or ")" but found ":"
on f(x) given mode:m           -- ❌ Expected end of line but found "given"
on f(x) with verbose           -- ❌ Expected end of line but found "with"
```

具名参数只存在于 **App 字典里定义的命令**（由 sdef 声明），不是语言特性。

### 推荐的「具名参数」替代方案：传记录 + 默认值

```applescript
on withDefaults(opts)
	-- ⚠️ 顺序很重要：opts 在前，默认值在后（同名字段「前者胜」）
	set merged to opts & {level:1, verbose:false, label:"x"}
	return merged
end withDefaults

my withDefaults({level:5})          --> {level:5, verbose:false, label:"x"}
my withDefaults({})                 --> {level:1, verbose:false, label:"x"}
my withDefaults({label:"y"})        --> {level:1, verbose:false, label:"y"}
```

⚠️ **记录用 `&` 合并时，同名字段以左边为准**（实测）：

```applescript
level of ({level:9} & {level:1})    --> 9
level of ({level:1} & {level:9})    --> 1
```

所以「用户参数覆盖默认值」必须写成 `opts & defaults`，写反了默认值会永远生效。

### 可选参数

AppleScript 没有可选参数语法，用 `missing value` 手动实现：

```applescript
on optParam(x, y)
	if y is missing value then set y to 100
	return x + y
end optParam

my optParam(1, missing value)   --> 101
my optParam(1, 5)               --> 6
```

⚠️ 调用时**必须显式传 `missing value`**，不能少传参数，否则报「参数个数不对」。

### 递归

```applescript
on factorial(n)
	if n <= 1 then return 1
	return n * my factorial(n - 1)      -- ⚠️ 递归调用也要加 my
end factorial

my factorial(6)   --> 720
```

⚠️ AppleScript 没有尾递归优化，递归深度过大会栈溢出。批量处理请用循环。

## 5.4 内置 handler（生命周期）

这些是「特殊入口」，由运行环境自动调用：

| handler | 触发时机 |
| --- | --- |
| `on run` | 脚本被执行（无参数时也可省略 `on run … end run` 外壳） |
| `on run argv` | 同上，`argv` 是命令行参数列表 |
| `on open droppedItems` | 有文件/文件夹被拖到 droplet 上 |
| `on idle` | stay-open applet 每隔 N 秒调用一次，返回值是下次间隔秒数 |
| `on quit` | applet 被要求退出，必须写 `continue quit` 才会真的退出 |

```applescript
property tickCount : 0

on run
	log "启动"
end run

on idle
	set tickCount to tickCount + 1
	log "第 " & tickCount & " 次心跳"
	return 30          -- 30 秒后再调用；返回 0 表示用默认间隔
end idle

on quit
	log "退出前保存状态"
	continue quit      -- ⚠️ 不写这行，applet 就不会退出
end quit
```

⚠️ `on idle` 只在用 `osacompile -s` 编译成 **stay-open applet** 后才会触发。
普通 `.scpt` 或 `osascript` 执行不会循环。

### droplet（拖放处理器）

```applescript
on open droppedItems
	repeat with anItem in droppedItems
		set itemPath to POSIX path of (anItem as alias)
		log "收到：" & itemPath
	end repeat
end open
```

编译成 droplet：在 Script Editor 里 文件 → 导出 → 文件格式选 **应用程序**，
勾上「拖放」（或者用 `osacompile -o Droplet.app` 并加上 `on open` handler，编译工具会自动识别）。

## 5.5 script 对象（面向对象的最小实现）

`script … end script` 可以定义带状态和方法的对象，也能继承：

```applescript
script Counter
	property n : 0
	on bump()
		set n to n + 1
		return n
	end bump
	on reset()
		set n to 0
	end reset
end script

Counter's bump()      --> 1
Counter's bump()      --> 2   ⚠️ property 的值会持久保存
```

⚠️ **`property` 的值在编译后的 `.scpt`/`.app` 里会被保存下来**，下次运行仍是上次的值。
这在 `osascript` 直接跑纯文本源码时不会发生（每次重新编译）。
调试时如果发现「变量莫名其妙有上次的值」，就是这个原因。

### 继承与 `continue`

用 `property parent : 父script` 建立继承，`continue 命令名` 调用父类实现：

```applescript
script BaseLogger
	property prefix : "[LOG]"
	on writeMsg(msg)
		return prefix & " base:" & msg
	end writeMsg
end script

script FileLogger
	property parent : BaseLogger
	property prefix : "[FILE]"
	on writeMsg(msg)
		set baseResult to continue writeMsg(msg)   -- 调用父类
		return baseResult & "|child"
	end writeMsg
end script

FileLogger's writeMsg("hi")   --> "[LOG] base:hi|child"
BaseLogger's writeMsg("hi")   --> "[LOG] base:hi"
```

⚠️ 注意上面结果是 `[LOG]` 而**不是** `[FILE]`（实测）。
`continue writeMsg(msg)` 是在**父 script 的上下文**里执行的，它读到的 `prefix` 是父类自己的属性，
子类的同名 `property` 并不会「虚函数式」地覆盖进去。

要实现多态，别依赖父类读属性，而是让父类调用一个可被子类重写的方法，或者干脆放弃继承、
用「组合 + 传参」：

```applescript
script Logger
	on writeMsg(msg, prefix)
		return prefix & " " & msg
	end writeMsg
end script

Logger's writeMsg("hi", "[FILE]")   --> "[FILE] hi"
Logger's writeMsg("hi", "[LOG]")    --> "[LOG] hi"
```

对绝大多数自动化脚本来说，**普通 handler + 记录参数** 已经足够，不必上 script 对象。

## 5.6 `run script` 与 `load script`

```applescript
-- 执行字符串形式的脚本
set r to run script "return 6 * 7"      --> 42

-- 带参数执行（参数进入对方的 on run argv）
set src to "on run {a, b}
	return a & b
end run"
run script src with parameters {"x", "y"}    --> "xy"

-- 加载外部脚本文件作为库
set lib to load script (POSIX file "/path/to/lib.scpt")
lib's someHandler()
```

⚠️ `run script "字符串"` 每次调用都要重新编译，**在循环里用会非常慢**。
要复用请 `load script` 一次，缓存返回值。

⚠️ `run script` 里抛出的错误，错误信息会带上 `脚本 …` 前缀，行号指向的是被执行的字符串，不好定位。

### 用 load script 组织代码库

```applescript
-- 主脚本
set stdlibPath to ((path to me as text) & "::lib:stdlib.scpt")
set stdlib to load script alias stdlibPath
stdlib's splitText("a,b,c", ",")
```

⚠️ `path to me` 只在编译后的脚本里有效；`osascript xxx.applescript` 跑纯文本时会失败。
更稳的做法是用绝对路径，或者通过命令行参数传入库路径（见 `examples/lib/stdlib.applescript`）。

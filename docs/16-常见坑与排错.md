# 16 常见坑与排错

本章每一条都是在本机（macOS 26.6.2）**实际跑出过错误**后总结的，附真实报错信息。
遇到怪问题时先来这里对照。

---

## 16.1 编译期错误（-2740 / -2741 / -2742）

### ① `use framework` 顶掉了标准命令 ⭐最常见的坑

**症状**：加了 `use framework "Foundation"` 之后，脚本突然全线报语法错误：

```
syntax error: A class name can't go after this identifier. (-2740)
syntax error: Expected "," but found class name. (-2741)
```

出错的往往是 `current date`、`do shell script`、`display dialog`、`path to`、`quoted form of` 这些
**本来一直好好的**语句。

**原因**：这些命令来自 Standard Additions。写了 `use framework` 后，
AppleScript 不再自动加载 scripting additions 的术语。

**解法**：紧跟一行 `use scripting additions`

```applescript
use framework "Foundation"
use scripting additions          -- ✅ 必加

set d to current date            -- 现在能用了
```

实测对照：

```applescript ❌
use framework "Foundation"
return (current date) as string
-- ❌ 43:47: script error: Expected "," but found class name. (-2741)
```

```applescript
use framework "Foundation"
use scripting additions
return (current date) as string
-- ✅ Monday, November 16, 2026 at 22:55:46
```

---

### ② 连续 `as` 不加括号

```applescript
month of d as integer as text          -- ❌ A class name can't go after this identifier (-2740)
((month of d) as integer) as text      -- ✅
```

---

### ③ 变量名撞上关键字（含未公开的）

实测**无法用作变量名**的一批，报错五花八门：

| 变量名 | 报错 |
| --- | --- |
| `st` `nd` `rd` `th` | `Expected expression but found "st"` (-2741) |
| `the` | `Expected expression but found "to"` (-2741) |
| `as` `is` `in` `of` `to` `if` `on` `or` `my` `ref` | 各种 -2740/-2741 |
| `its` | `A "to" can't go after this "its"` (-2740) |
| `it` `me` | `Can't set … Access not allowed` (-10003) |
| `line` `text` `item` | `Can't set line to 5. Access not allowed` (-10003) |
| `no` `up` | 同上 (-10003)，它们是枚举常量 |
| `app` | `Can't set application to 1` (-10003) |
| `id` `key` | `Can't set id to 1` (-10006) |
| `log` | `Can't set log of 1 to …` (-10006) |
| `expanded` | `Can't set expanded to …  Access not allowed` (-10003)，撞上 AX 的 `expanded` 属性 |
| `result` | ⚠️ **能赋值但会被静默覆盖**，见 §16.2⑳ |

⚠️ **`st`/`nd`/`rd`/`th` 特别坑**：它们是序数后缀（`1st`、`2nd`…）被单独当成了保留标记。
写日期脚本时 `set nd to current date`、写播放器脚本时 `set st to player state` 都太自然了，
但报错信息（`Expected expression but found "st"`）完全看不出原因。

⚠️ **`line` 更坑**：逐行处理文本文件时几乎必然会用到它，而它连循环变量都当不了：

```applescript ❌
repeat with line in {"a", "b"}   -- ❌ Expected variable name or property but found class name. (-2741)
end repeat

repeat with ln in {"a", "b"}     -- ✅ ln / theLine / aLine
end repeat
```

**解法**：变量名至少两个单词（`targetDate`、`fileList`），见 §2.9。

---

### ④ AppleScript 标识符大小写不敏感 → 撞 ObjC 类名

```applescript
set nsArray to current application's NSArray's arrayWithArray:lst
-- ❌ nsArray doesn't understand the "arrayWithArray_" message. (-1708)
```

**原因**：`nsArray` 和 `NSArray` 忽略大小写后相同，编译器把 `NSArray` 解析成了你的局部变量。

**解法**：改名 `theArray` / `cocoaArray`。同理避免 `nsString`、`nsDate`、`nsNumber`。

---

### ⑤ `round x to n` 不存在

```applescript ❌
round 3.14159 to 2      -- ❌ A "to" can't go after this real number (-2740)
```

`round` 只有 `rounding` 一个可选参数，**永远返回 integer**。保留小数位要自己写（见 §4.7）。

---

### ⑥ 用户 handler 不支持具名参数

```applescript ❌
on f(a, level:theLevel)   -- ❌ Expected "," or ")" but found ":" (-2741)
on f(x) given mode:m      -- ❌ Expected end of line but found "given" (-2741)
on f(x) with verbose      -- ❌ Expected end of line but found "with" (-2741)
```

具名参数只属于 App 字典里声明的命令。替代方案：传记录 + `&` 合并默认值（见 §5.3）。

---

### ⑦ 续行符 `¬` 后面有空格

```applescript ❌
set x to someCommand(a, ¬   ← 这里如果有空格，编译失败
	b)
```

`¬` 必须是行内最后一个字符。用 Option+L 输入。

## 16.2 运行期错误

### ① -1700 Can't make X into type Y

三种典型来源：

**a) 把「引用列表」当文本用**

```applescript
set lst to {"a", "b", "c"}
set refs to {}
repeat with anItem in lst
	set end of refs to anItem          -- 存进去的是引用！
end repeat
refs as text
-- ❌ Can't make {item 1 of {"a","b","c"}, item 2 of …, …} into type text (-1700)

-- ✅
set end of refs to (contents of anItem)
```

**b) `butlast` 返回引用而非列表**

```applescript
(butlast of {1,2,3}) as text          -- ❌ -1700
butlast of {1,2,3}                    -- ❌ -1728 Can't get butlast of …
(items 1 thru -2 of {1,2,3}) as text  -- ✅ "12"
```

**c) 类型转换失败**

```applescript
"abc" as integer                      -- ❌ -1700
```

---

### ② -1708 doesn't understand the "xxx" message

九成是**术语解析问题**（见 §7.2）：

- 在 `tell` 块里调用自己的 handler 忘了 `my`
- 在 `tell` 块里调用 Standard Additions 命令忘了 `my`
- 变量名 `nsArray` 撞了 ObjC 类名（见 §16.1④）
- 真的拼错了命令名 → 用 `sdef` 核对

---

### ③ -1727 Expected a reference（Finder 特有）

```applescript
tell application "Finder"
	count items of someAlias                  -- ❌ -1727
	count of (every item of someAlias)        -- ❌ -1727
end tell
```

**可行的写法**（实测）：

```applescript
-- ① 用 HFS 路径 + folder
tell application "Finder"
	set n to count of (items of folder "Macintosh HD:private:tmp:asv:ftest:")
end tell

-- ② 先取列表到变量，再在 tell 外面 count
tell application "Finder"
	set theList to every item of theFolder
end tell
set n to count of theList

-- ③ 干脆不用 Finder
tell application "System Events"
	set n to count of files of folder "/private/tmp/asv/ftest"
end tell
```

### ④ -1728 Can't get …

| 场景 | 说明 |
| --- | --- |
| `POSIX file "/x" as alias` | **文件不存在**。`as alias` 要求已存在 |
| Finder 报 `… wasn't found. (-43)` | 路径错，或用了 `/tmp` 这类符号链接（改用 `/private/tmp`） |
| `name of logs`（logs 是 whose 的结果列表） | 见下 |
| `tell application "不存在的App"` | App 名拼错 |

**`whose` 结果不能直接取属性**：

```applescript
set logs to (every file of theFolder whose name extension is "log")
set logNames to name of logs        -- ❌ Can't get name of {document file …} (-1728)

-- ✅ 内联
set logNames to name of (every file of theFolder whose name extension is "log")
-- ✅ 或手动循环
set logNames to {}
repeat with f in logs
	set end of logNames to (name of f)
end repeat
```

### ⑤ Finder 引用改名后失效

```applescript
tell application "Finder"
	set nf to make new folder at theFolder with properties {name:"tmpA"}
	set name of nf to "tmpB"
	name of nf                              -- ❌ -1700 / -43，nf 还指着 "tmpA"
	set nf2 to folder "tmpB" of theFolder   -- ✅ 重新取
end tell
```

**改名/移动之后必须重新获取引用。**

### ⑥ -1743 / -25211 / -15000：权限

| 错误码 | 含义 | 解决 |
| --- | --- | --- |
| -1743 | 自动化权限被拒 | 系统设置 → 隐私与安全性 → **自动化** |
| -25211 | 辅助功能权限缺失 | 系统设置 → 隐私与安全性 → **辅助功能** |
| -15000 | 未授权发送 Apple Event | 同上 |
| -120 | 目录访问被拒 | **文件与文件夹** / **完全磁盘访问** |

⚠️ 授权对象是**宿主程序**（终端 / Script Editor / 你的 applet），不是脚本。
改完权限要 **⌘Q 完全退出宿主再重开**。

彻底重置授权（让弹框重新出现）：

```bash
tccutil reset AppleEvents com.apple.Terminal
tccutil reset Accessibility com.apple.Terminal
```

### ⑦ -49 / -50：文件句柄泄漏

`open for access` 之后没有 `close access`，后续再打开同一文件就会失败。

```applescript
set fh to missing value
try
	set fh to open for access theFile with write permission
	write theText to fh starting at eof as «class utf8»
	close access fh
on error errMsg number errNum
	if fh is not missing value then
		try
			close access fh
		end try
	end if
	error errMsg number errNum
end try
```

### ⑧ 日期被意外修改（引用语义）

```applescript
on startOfDay(theDate)
	set t to theDate        -- ⚠️ 没有拷贝！
	set time of t to 0
	return t
end startOfDay

set d to current date
my startOfDay(d)
time of d                   --> 0   ⚠️ 原来的 d 被改了
```

**解法**：`copy theDate to t`。

同理适用于 list、record。handler 参数是按引用传的，连 `set localVar to theParam` 都不是拷贝。

### ⑨ `do shell script` 换行变成 CR

```applescript
do shell script "printf 'a\\nb'"
-- 得到 id 97, 13, 98   ← 13 是 CR，不是 LF(10)
```

**解法**：`altering line endings false`，或按 `return` 切分。见 §12.2。

### ⑩ `if` 的条件必须是 boolean

```applescript
if 0 then …       -- ❌ 运行时 -1700 Can't make 0 into type boolean
if "" then …      -- ❌ 同样
if {} then …      -- ❌ 同样
```

⚠️ 这是**运行期**错误，编译（⌘K）不报，很容易漏到生产。

### ⑪ `giving up after 0` = 永不超时

```applescript
display dialog "…" giving up after 0    -- ⚠️ 脚本永久阻塞
display dialog "…" giving up after 1    -- ✅ 1 秒后自动关闭
```

### ⑫ `choose from list` 取消返回 `false`，不抛错

```applescript
set theChoice to choose from list {"a", "b"}
if theChoice is false then return      -- ✅ 必须这样判断
-- 用 try 捕获 -128 是无效的
```

### ⑬ `with timeout` 管不到 `delay` 和本地循环

```applescript
with timeout of 1 second
	delay 3        -- ⚠️ 实测等满 3 秒，不会中断
end timeout
```

`with timeout` 只对 **Apple Event 往返**生效。本地耗时任务要自己做截止时间判断。

### ⑭ `record` 的 `name` 键桥接时会丢

```applescript
-- 实测 allKeys 结果
{name:"T", age:30, city:"SH"}        --> {"age", "city"}      ⚠️ name 消失
{|name|:"T", age:30}                 --> {"name", "age"}      ✅
{firstName:"T", age:30}              --> {"firstName", "age"} ✅
```

**记录键名避开 `name`、`id`、`class`、`text`、`URL`** 这些标准属性名。

---

### ⑮ 记录合并方向搞反

```applescript
level of ({level:9} & {level:1})    --> 9    ← 左边优先
level of ({level:1} & {level:9})    --> 1
```

所以「用户参数覆盖默认值」必须写 `opts & defaults`。写反了默认值永远生效，
且**不报任何错**，纯粹是行为不对。

---

### ⑯ 循环中改正在遍历的列表

会跳过元素或死循环。要么先 `copy`，要么倒序索引：

```applescript
repeat with i from (count of lst) to 1 by -1
	if shouldRemove(item i of lst) then delete item i of lst
end repeat
```

### ⑰ `property` 的值会被持久化

编译成 `.scpt` / `.app` 后，`property` 的值**会保存上次运行的结果**，下次启动仍在。

```applescript
property counter : 0
on run
	set counter to counter + 1
	return counter      -- 第二次运行返回 2，不是 1
end run
```

调试时「变量怎么有上次的值」多半是这个原因。
`osascript xxx.applescript` 跑纯文本每次重新编译，不会有这个现象 —— 所以本地正常、打包后异常。

### ⑱ `load script` 加载纯文本 `.applescript` 会报 -1752

```applescript
set lib to load script (POSIX file "/path/to/stdlib.applescript")   -- ⚠️ 纯文本源码
lib's splitText("a,b", ",")        -- ✅ 纯计算函数侥幸能用
lib's fileExists("/tmp/a.txt")     -- ❌ -1752 Script doesn't seem to belong to AppleScript.
```

**原因**：从纯文本源码临时编译出的 script 对象，其内部 `tell application "System Events"`
找不到合法的「归属脚本」上下文。凡是函数体里带 `tell application …` 的 handler 都会失败。

**解法**：先编译成 `.scpt` 再 load —— 实测完全正常：

```bash
osacompile -o stdlib.scpt stdlib.applescript
```

```applescript
set lib to load script (POSIX file "/path/to/stdlib.scpt")
lib's fileExists("/tmp/a.txt")     -- ✅ true
```

⚠️ 记得把 `.scpt` 加进构建步骤，不要提交到版本库（源码 `.applescript` 才是唯一真源）。

### ⑲ `set lines to …` 报错

```applescript
set lines to {"a", "b"}     -- ❌ Can't set every line to {"a","b"} (-10006)
set theLines to {"a", "b"}  -- ✅
```

`lines`、`words`、`paragraphs`、`items`、`characters` 这些复数名词会被解析成「every X」。

⚠️ 注意报错时机不一样，很容易误判：

| 写法 | 编译 | 运行 |
| --- | --- | --- |
| `set lines to {"a","b"}` | ✅ 通过 | ❌ -10006 `Can't set every line to …` |
| `set words to {"a"}` / `paragraphs` / `characters` / `items` | ✅ 通过 | ❌ -10006 `Can't set every word to …` |
| `set line to "abc"`（单数） | ❌ -10003 `Access not allowed` | 跑不到 |
| `set text to "abc"` / `item` / `it` / `me` | ❌ -10003 | 跑不到 |

复数是**运行期**才炸（所以 Script Editor 里 ⌘K 编译看不出问题），单数是**编译期**就炸。

### ⑳ `result` 是隐式全局，每条语句后都会被自动覆盖 ⚠️⚠️

`result` 不是普通变量名——它是 AppleScript 保存「上一条语句返回值」的隐式全局。
**所以拿它当累加器，一定会坏，而且坏得毫无征兆。**

本机实测：

```applescript
set result to {}
set t to "hello"
return {resultClass:(class of result), resultValue:(result as text)}
--> {resultClass:text, resultValue:"hello"}     ← 空列表变成了字符串！

-- 对照组：换个名字就正常
set theResult to {}
set t to "hello"
return class of theResult
--> list
```

实际踩到的样子（一个「列出目录」的函数）：

```applescript
set result to {}
repeat with anItem in theList
	set t to anItem as text        -- ← 这条语句把 result 覆盖成了字符串
	if t is not "" then set end of result to t   -- ❌ Can't set end of "…" to "…" (-10006)
end repeat
```

⚠️ 报错信息是 `Can't set end of <字符串> to <字符串>`，看起来像「列表操作失败」，
实际根因是 `result` 被上一条 `set t to …` 悄悄改掉了。**极难排查。**

**解法**：永远不要用 `result` 当变量名。用 `theResult`、`acc`、`outList`。

### ㉑ record 的键必须先存在，才能 `set X of rec to …`

```applescript
set rec to {name:"a"}
set name of rec to "b"        -- ✅ 键已存在
set age of rec to 10          -- ❌ -10006 errAECantAssign
-- Can't set age of {name:"a"} to 10
```

AppleScript 的 `set <key> of <record> to …` **只能改已存在的键，不能新增键**。
新增键只有两种办法：

```applescript
-- 办法一：建 record 时就把所有键写全（推荐，可读性最好）
set rec to {name:"a", age:0, tags:{}}
set age of rec to 10

-- 办法二：用 & 合并（注意左边优先，见 §16.2⑮）
set rec to {age:10} & rec
```

⚠️ 这个坑在「解析文件 → 逐字段填充 record」的脚本里几乎必踩，
因为写的时候很自然会 `set startDate of rec to …`。

---

### ㉒ 取子串越界 → -1728

```applescript
text 3 thru -1 of "1h"        -- ❌ Can't get text 3 thru -1 of "1h". (-1728)
```

`text m thru n of s` 里 `m` 超过字符串长度就直接报错，**不会**返回空串。
切分「1h」「45m」这类紧凑格式时必须先判长度：

```applescript
if hPos < (length of t) then
	set t to text (hPos + 1) thru -1 of t
else
	set t to ""
end if
```

## 16.3 排错流程（按顺序走）

### 第 1 步：把错误信息读全

```applescript
try
	-- 出问题的代码
on error errMsg number errNum from errFrom to errTo
	log "消息: " & errMsg
	log "编号: " & errNum
	log "来源: " & (errFrom as text)
	log "目标: " & (errTo as text)
end try
```

### 第 2 步：分清是编译错误还是运行错误

- **script error / syntax error**（-27xx）→ 编译期，看语法、关键字、变量名
- **execution error**（-17xx / -1xx / -4x）→ 运行期，看权限、路径、类型

### 第 3 步：缩小范围

```bash
# 把可疑的表达式单独拿出来跑
osascript -e 'set d to current date' -e 'return (year of d as text)'

# 检查类型（类型错误占一半以上）
osascript -e 'return (class of someExpression) as text'

# 看清楚数据结构
osascript -s s -e 'return someComplexValue'
```

### 第 4 步：怀疑术语解析就加 `my`

在 `tell` 块里，给自己脚本的 handler、Standard Additions 命令、脚本顶层 property **统统加 `my`**，
错误消失就说明是解析问题。

### 第 5 步：怀疑权限就单独测

```applescript
-- 自动化权限
try
	tell application "Finder" to get name of startup disk
	log "Finder OK"
on error e number n
	log "Finder FAIL #" & n & ": " & e
end try

-- 辅助功能权限
tell application "System Events"
	log "UI elements enabled: " & (UI elements enabled as text)
end tell
```

### 第 6 步：用 sdef 核对术语

```bash
sdef /Applications/Safari.app | grep -A10 '<command name="do JavaScript"'
```

不要凭记忆或网上的旧帖子写命令名 —— **App 字典是唯一权威**。

### 第 7 步：开 Script Editor 的事件日志

⇧⌘2 打开，能看到每条 Apple Event 的发送内容和 App 的回复，
是排查「App 不听话」的最终手段。

### 第 8 步：脚本「死住了」（不报错、也不返回）

没有错误信息的卡死，几乎只有三种原因，按这个顺序排查：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 屏幕上有弹窗没点（授权框、`display dialog`、App 自己的模态窗） | 事件在等用户回应 | 先手动点掉；无人值守场景要预先授权（§15.4） |
| 所有涉及 System Events 的脚本都卡 | System Events 被上一次调用卡死 | `killall "System Events"`（launchd 自动重启），见 §16.5⑭ |
| 只有某一条语句卡 | 目标 App 在忙/无响应，或该调用本身不支持超时 | 用 `with timeout of N seconds` 包住，超时会得到 -1712 |

```bash
# System Events 健康检查：5 秒内不回就是卡死了
osascript -e 'with timeout of 5 seconds' \
          -e 'tell application "System Events" to name of first process whose frontmost is true' \
          -e 'end timeout'
```

⚠️ 强行 `kill` 正在发 Apple Event 的 `osascript` 进程，**本身就可能把目标 App（尤其 System Events）留在卡死状态**。
所以 kill 完记得做一次上面的健康检查，必要时 `killall "System Events"`。

## 16.4 性能陷阱速查

| 慢的写法 | 快的写法 |
| --- | --- |
| `set lst to lst & {x}`（循环里） | `set end of lst to x` |
| `set beginning of lst to x`（大列表） | 追加后再 `reverse` |
| `characters of` 处理长文本 | AppleScriptObjC 的 `NSString` 方法 |
| 循环里逐条 `tell application` | 一次取回列表，本地处理 |
| `repeat with x in lst` 里反复 `item i of lst` | 先 `count of lst` 存变量 |
| Finder 递归枚举整个目录树 | `do shell script "find …"` |
| `read` 几十 MB 文件 | `do shell script` + `grep`/`awk` |
| 循环里 `run script "字符串"` | `load script` 一次并缓存 |
| UI Scripting 不加 delay 疯狂重试 | 加 `delay 0.3`，用 `exists` 判断 |

### 基准测试

⚠️ `current date` **只精确到秒**，测短操作毫无意义。要毫秒级精度用 NSDate（实测可用）：

```applescript
use framework "Foundation"
use scripting additions

set t1 to (current application's NSDate's |date|())

-- …… 被测代码 ……
delay 0.3

set t2 to (current application's NSDate's |date|())
set elapsedMs to (round ((t2's timeIntervalSinceDate:t1) * 1000) rounding to nearest)
log "耗时 " & elapsedMs & " 毫秒"      -- 实测输出 302
```

封装成工具：

```applescript
use framework "Foundation"
use scripting additions

on nowMs()
	set t to (current application's NSDate's |date|())
	return (t's timeIntervalSince1970()) * 1000 as real
end nowMs

on run
	set t0 to my nowMs()
	-- …… 被测代码 ……
	log "耗时 " & (round (my nowMs() - t0) rounding to nearest) & " ms"
end run
```

⚠️ 测「循环里追加列表」这类差异时，记得跑至少 1000 次以上，否则 Apple Event 往返的噪声会盖过差异。

## 16.5 字典与 UI Scripting 专项坑

这一节的坑全部与「读字典」和「点界面」有关，配套阅读
`docs/08-读懂脚本字典与Suite语法.md`、`docs/10-SystemEvents与界面自动化.md`、
`docs/11-用AccessibilityInspector定位UI元素.md`。

### ① `whose` 子句语序错 → -1723「Access not allowed」

```applescript
tell application "System Events" to tell process "Safari"
	-- ❌ whose 放在了 of 链前面（注释掉才能编译）
	-- get every UI element whose role is "AXCell" of row 1 of table 1 of window 1
	-- 编译报错：Can’t get "AXCell" of row 1 …  Access not allowed. (-1723)

	-- ✅ whose 必须放在整个 of 链的最后
	get (every UI element of row 1 of table 1 of window 1 whose role is "AXCell")
end tell
```

⚠️ `-1723` 的信息写着「Access not allowed」，**极具误导性**——
它其实是语序错，跟权限一点关系都没有。看到 `-1723` 先检查 `whose` 的位置。

### ② `repeat with` 遍历 System Events 对象 → -1700 且带 `«class …»`

```applescript
-- ❌
tell application "System Events"
	repeat with p in (every process whose background only is false)
		log (p as text)
	end repeat
end tell
-- 实测报错：Can’t make «class pcap» "Terminal" of application "System Events"
--           into type text. (-1700)

-- ✅ 用 name of p
tell application "System Events"
	repeat with p in (every process whose background only is false)
		log (name of p)
	end repeat
end tell
```

⚠️ 注意报错里的 `«class pcap»`：`pcap` 是 `process` 类的四字符码。
**看到 `«»` 就是术语没解析成功**（§8.8），这里则是「循环变量是引用不是值」，
和 §16.2①a 是同一个根因。

### ③ 无辅助功能权限的报错码有三种，别查错误码表

同一个根因（宿主没有辅助功能权限），本机实测会报**三个不同的码**：

| 你写的代码 | 实测错误码 |
| --- | --- |
| `count of windows of process "X"` | `-25211` |
| `name of window 1 of process "X"` | `-1719` |
| `UI elements of window 1` | `-1719` |
| `name of every window of process "NotificationCenter"` | `-1728` |
| `keystroke "a"` | `-25211` |

而 `-1728` 官方含义是 `errAEUnknownObject`（找不到对象），`-1719` 是 `errAEIllegalAccess`，
两个都不像「权限问题」。

⚠️⚠️ **判断方法：看错误信息文本里有没有 `assistive access`，不要看错误码。**
本机实测 `-1728` 的完整信息是：

```
System Events got an error: osascript is not allowed assistive access. (-1728)
```

有 `assistive access` → 去授权（§15）；没有 → 才真的是定位/语法问题。

⚠️ 授权对象是**宿主进程**（终端 / Script Editor / 你的 .app），不是脚本；
且**授权后必须完全退出宿主再重开**才生效。

### ④ `fn down` 不存在 → -2741

```applescript
tell application "System Events"
	keystroke "a" using {command down}   -- ✅
	-- keystroke "a" using {fn down}     -- ❌ 编译失败
	-- Expected “,” or “}” but found application constant or consideration. (-2741)
end tell
```

本机 sdef 里 `eMds` 枚举**只有 4 个成员**：
`command down`（`Kcmd`）、`control down`（`Kctl`）、`option down`（`Kopt`）、`shift down`（`Ksft`）。
网上大量教程写 `fn down`，那是错的。

### ⑤ 硬编码本地化日期字面量 → -30720

```applescript
-- ❌ 本机（区域 en_CN）实测编译期就失败
-- set d to date "2026年11月20日 10:00:00"
-- 报错：Invalid date and time date 2026年11月20日 10:00:00. (-30720)
```

```applescript
-- ✅ 可移植写法
set d to (current date)
set year of d to 2026
set month of d to 11
set day of d to 20
set time of d to 10 * hours
```

⚠️ 日期字面量的可解析格式由**系统区域设置**决定。本机 `date "2026-11-20 10:00:00"`
能过，但换台机器不保证。生产脚本一律用「`current date` + 逐项赋值」。

### ⑥ `sdef` 拿不到 ≠ App 不可脚本化

```bash
sdef /System/Applications/Safari.app
# sdef: couldn't get sdef for /System/Applications/Safari.app (error -43)
```

Safari 的字典受系统保护，`sdef` 报 `-43`，**但 Script Editor ⇧⌘O 能正常打开，
Safari 也完全可脚本化**。遇到 `-43` 改用 Script Editor。

反过来，`Preview.app` / `TextEdit.app` 是真的没有有意义的字典，只能走 UI Scripting。

### ⑦ `sdef` 不展开 `xi:include`

```bash
sdef /System/Applications/Notes.app | grep -c '<command name="make"'
# 0     ← 明明每个 App 都支持 make
```

Standard Suite 是通过 `xi:include` 从 `/System/Library/ScriptingDefinitions/CocoaStandard.sdef`
引入的，**`sdef` 不会内联它**。Script Editor 会展开，命令行不会。
用 `tools/sdef2txt.py`（已自动内联）或单独 dump 那个公共文件。

### ⑧ `grep '<class name='` 会漏掉 `class-extension`

System Events 的 sdef 里搜不到 `<class name="window">`，只有
`<class-extension extends="window">`。所以「grep 不到」不等于「没有这个类」。
统计类要同时匹配两种标签（§8.4）。

### ⑨ Hidden Suite 在 Script Editor 字典里看不见

`pick`、`confirm`、`cancel`、`increment`、`decrement`、`key down`、`key up` 都在
System Events 的 `Hidden Suite` 里，**字典窗口不显示但确实能用**。
本机 System Events 的 sdef 里有 59 处 `hidden="yes"`。
查完整能力只能读 sdef 原文（§8.8）。

### ⑩ 系统弹窗不在你正在操作的进程里

```applescript
-- ❌ 永远找不到「Safari 想访问你的位置」这个弹窗
tell application "System Events" to tell process "Safari"
	click button "允许" of window 1
end tell
```

本机实测，TCC 权限弹窗的宿主是 **`UserNotificationCenter`**
（bundle id `com.apple.UserNotificationCenter`），通知横幅的宿主是
**`NotificationCenter`**（bundle id `com.apple.notificationcenterui`）。
定位方法见 §10.5.10 类别 C。

⚠️ 而且**不要试图自动点掉权限弹窗**：需要权限才能点授予权限的弹窗，逻辑上死循环。
正确解法是预先授权（§15）。

### ⑪ `attribute "AXxxx"` 不支持时抛错，不是返回 `missing value`

```applescript
tell application "System Events" to tell process "Safari"
	-- ❌ button 上没有 AXModal，会直接抛错（注释掉才能编译）
	-- get value of attribute "AXModal" of button 1 of window 1

	-- ✅ 永远套 try
	try
		set isModal to (value of attribute "AXModal" of window 1)
	on error
		set isModal to false
	end try
end tell
```

⚠️ 同理，`UI element` 的 19 个原生属性里很多带 `| missing value | any`，
不同控件返回类型不同（§10.5.3），也要 `try` 兜底。

### ⑫ 想当然的术语：`default calendar` 不存在

```applescript ❌
tell application "Calendar"
	set c to default calendar
	-- ❌ 编译失败：Expected end of line but found class name. (-2741)
end tell
```

本机 Calendar 的 sdef 实测：`application` 的 `class-extension` 里**只声明了
`calendar` 一种 element**，没有任何 `default …` 属性。
「默认日历」这个概念在 EventKit 里有（`EKEventStore defaultCalendarForNewEvents`），
但**没有暴露给 AppleScript**。

替代方案：

```applescript
tell application "Calendar"
	set c to calendar 1                  -- 第一个日历（顺序即 Calendar 里的排序）
	get name of every calendar           -- 先列出来让用户/日志确认
end tell
```

⚠️ 这类「听起来很合理但字典里没有」的术语还有不少。
**唯一的确认方法是查字典**（§8.2、§8.5），不要凭英语直觉猜。
`-2741` + `found class name` 基本就等于「这个词在这个 App 的字典里不存在」。

### ⑬ 相对路径在 System Events 里不生效，但 `do shell script "pwd"` 能拿到 cwd

直觉上会以为 `do shell script` 从 `$HOME` 出发、拿不到调用者的当前目录。
**本机实测是相反的**——它确实继承 cwd：

```bash
cd /tmp && osascript -e 'do shell script "pwd"'          # → /tmp
cd ~/Desktop/applescript && osascript -e 'do shell script "pwd"'
#                                                        # → /Users/taylor/Desktop/applescript
```

真正不解析相对路径的是 **System Events**：

```applescript
-- 当前目录是 /Users/taylor/Desktop/applescript
tell application "System Events"
	exists file "README.md"                                    --> false  ❌ 相对路径不认
	exists file "/Users/taylor/Desktop/applescript/README.md"  --> true   ✅ 本机实测
end tell
```

**解法**：用 `do shell script "pwd"` 把相对路径拼成绝对路径。

```applescript
on resolvePath(p)
	if p starts with "/" then return p
	if p starts with "~/" then
		return (POSIX path of (path to home folder)) & (text 3 thru -1 of p)
	end if
	return (do shell script "pwd") & "/" & p
end resolvePath
```
✅ 实测：拼出的绝对路径 `exists file` 返回 `true`。

⚠️⚠️ 但**只在文件确实存在时这么用**。拿 `exists file` 去查一个**不存在**的文件，
在 TCC 保护目录里会把 System Events 整个卡死，见 §16.5⑭。

⚠️ 但这只对 `osascript` 生效。**双击运行 .applet 时没有「调用者 cwd」**，
`pwd` 会返回 `/`。所以生产脚本最好按多个候选依次尝试：

```applescript
on resolveInputPath(rawPath, lib)
	set candidates to {}
	set end of candidates to my expandTilde(rawPath)
	set end of candidates to (do shell script "pwd") & "/" & rawPath
	set end of candidates to (my ownDir()) & "/" & rawPath
	repeat with c in candidates
		if lib's fileExists(c) then return c
	end repeat
	error "输入文件不存在：" & rawPath & "（已尝试 " & (count of candidates) & " 个路径）"
end resolveInputPath
```

注意上面的 `lib's fileExists()` 走的是 shell 的 `test -f`（§9.5），不是 System Events 的 `exists file`。

### ⑭ `exists file` 查「不存在的文件」会把 System Events 卡死 ⚠️⚠️

本机实测（详见 §9.5 的完整表格）：

| 查询目标 | 结果 |
| --- | --- |
| `~/Desktop/…/README.md`（存在，保护目录） | `true`，秒回 |
| `~/Desktop/…/nope.txt`（**不存在**，保护目录） | ⚠️⚠️ 挂起；带 `with timeout of 6 seconds` 时 6 秒后报 -1712 |
| `/tmp/nope.txt`（不存在，非保护目录） | `false`，秒回 |
| `README.md`（相对路径） | `false`，秒回（不挂起） |

更麻烦的是**卡死会传染**：那一次 -1712 之后，System Events 对**后续所有** Apple Event 都不再回应，
连 `name of first process whose frontmost is true` 也照样 -1712。

**恢复方法**（launchd 会自动重新拉起，不用手动启动）：

```bash
killall "System Events"
```

**预防**：

1. 判断文件/目录是否存在，一律用 shell：
   `do shell script "test -f " & quoted form of posixPath & " && echo yes || echo no"`。
2. 别用 `open for access` 试探——文件不存在时它会**直接创建一个 0 字节文件**（§9.5）。
3. 同类「查询语句把 System Events 卡住」的情况还有：**TCC 授权弹窗没人点**。
   弹窗期间 System Events 不处理任何事件，脚本看起来就是「死住了」。
   所以调 UI 脚本前先确认权限已授予（§15.4），别让弹窗出现在无人值守的定时任务里。
